CDK separates permissions into three layers:

1. The bootstrap operator creates `CDKToolkit` and its publishing, lookup,
   deployment, and CloudFormation execution roles.
2. The GitHub caller assumes the bootstrap roles and pushes the two PayLens ECR
   images. It does not directly create stack resources.
3. CloudFormation assumes the execution role carrying
   `PayLensPilotCloudFormationExecutionPolicy` and creates only the service
   families represented in the synthesized templates.

## Approach A: temporary development-account administrator

Use this only for an account administrator to establish the bootstrap and
permanent roles. Attach `AdministratorAccess` to a short-lived bootstrap role
or, if account policy requires it, temporarily to the current development user.
Require MFA, record the change, and remove it immediately after bootstrap and
role creation.

Before bootstrapping, create two customer-managed policies from
`infrastructure/iam/cloudformation-execution-core-policy.example.json` and
`infrastructure/iam/cloudformation-execution-edge-data-policy.example.json`.
They are split to remain under IAM's managed-policy document size limit. Name
them `PayLensPilotCloudFormationCore` and
`PayLensPilotCloudFormationEdgeData`. Bootstrap both regions with both policy
ARNs so the permanent execution role does not default to administrator:

```powershell
$Account="169133351222"

aws iam create-policy `
  --policy-name PayLensPilotCloudFormationCore `
  --policy-document file://infrastructure/iam/cloudformation-execution-core-policy.example.json
aws iam create-policy `
  --policy-name PayLensPilotCloudFormationEdgeData `
  --policy-document file://infrastructure/iam/cloudformation-execution-edge-data-policy.example.json

$CorePolicyArn="arn:aws:iam::$Account`:policy/PayLensPilotCloudFormationCore"
$EdgeDataPolicyArn="arn:aws:iam::$Account`:policy/PayLensPilotCloudFormationEdgeData"
$ExecutionPolicies="$CorePolicyArn,$EdgeDataPolicyArn"

cd infrastructure
npm ci
npx cdk bootstrap "aws://$Account/eu-north-1" `
  --cloudformation-execution-policies $ExecutionPolicies
npx cdk bootstrap "aws://$Account/us-east-1" `
  --cloudformation-execution-policies $ExecutionPolicies

aws cloudformation describe-stacks --stack-name CDKToolkit --region eu-north-1
aws cloudformation describe-stacks --stack-name CDKToolkit --region us-east-1
aws ssm get-parameter --name /cdk-bootstrap/hnb659fds/version --region eu-north-1
aws ssm get-parameter --name /cdk-bootstrap/hnb659fds/version --region us-east-1
```

After verification, detach the temporary administrator policy and verify it is
gone. Do not use this identity in GitHub Actions.

## Approach B: GitHub OIDC deployment role

Create the GitHub OIDC provider for
`https://token.actions.githubusercontent.com` with audience
`sts.amazonaws.com` if it does not exist. Create
`PayLensPilotGitHubDeployRole` using
`infrastructure/iam/github-oidc-trust-policy.example.json` and attach
`infrastructure/iam/github-deploy-policy.example.json`.

After verifying the committed immutable repository identity, an administrator
can create the role and its caller policy without creating an access key:

```powershell
aws iam create-role `
  --role-name PayLensPilotGitHubDeployRole `
  --assume-role-policy-document file://infrastructure/iam/github-oidc-trust-policy.example.json
aws iam put-role-policy `
  --role-name PayLensPilotGitHubDeployRole `
  --policy-name PayLensPilotGitHubDeploy `
  --policy-document file://infrastructure/iam/github-deploy-policy.example.json
```

The workflow requests only `id-token: write` and `contents: read` and uses the
protected GitHub environment `pilot`. GitHub's immutable environment subject
includes the owner ID, repository ID, and environment, so IAM restricts the
exact repository identity and environment. Enforce the branch separately in
the GitHub `pilot` environment's deployment-branch rules: allow only `main`,
require reviewers, and prevent self-review.

Set `AWS_DEPLOY_ROLE_ARN` to the role ARN as a GitHub environment secret. Keep
`BUDGET_ALERT_EMAIL` and `ORIGIN_VERIFY_HEADER` there as well. Never create or
store an AWS access key in GitHub.

The GitHub role can assume only the `hnb659fds` deploy, file-publishing,
image-publishing, and lookup roles for account `169133351222` in `eu-north-1`
and `us-east-1`. Its direct `iam:PassRole` is restricted to PayLens ECS roles
and `ecs-tasks.amazonaws.com`. CloudFormation permissions remain in the
separate execution role.
